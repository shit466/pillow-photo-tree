# 枕头的照片树 · Demo

深色星空中的 Three.js 照片圣诞树，支持触控、摄像头手势、照片聚焦、照片宇宙与隐藏三次愿望券。当前使用 12 张本地压缩的风景示例照片，替换照片不需要修改场景核心代码。

## 本地运行

需要 Node.js 22.12+。

```bash
npm install
npm run dev -- --host 0.0.0.0
```

打开终端显示的本地地址。电脑 `localhost` 可以申请摄像头权限；手机通过局域网 HTTP 地址访问时，请使用触控。手机摄像头测试需要 HTTPS 公网地址，或者开发机配置受信任的 HTTPS 证书。

```bash
npm run build
npm run preview -- --host 0.0.0.0
```

构建结果在 `dist/`。项目使用相对 `base: './'`，适用于 GitHub Pages 的仓库子路径，也适用于静态托管根路径。

## 用 GitHub 链接打开

1. 将本项目作为 GitHub 仓库根目录上传，保留 `.github/workflows/`。
2. 在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。
3. 推送到 `main`，等待 Pages 工作流安装依赖、执行构建并发布 `dist/`。
4. 在 Pages 设置页或部署记录取得 `https://用户名.github.io/仓库名/`，手机 Safari 或 Chrome 可直接打开。

仓库不要求 Vercel 或 Cloudflare 账号。若使用 Vercel / Cloudflare Pages，构建命令同样是 `npm run build`，输出目录是 `dist`。摄像头授权应在顶层 HTTPS 页面测试，避免浏览器内嵌预览对权限的限制。

## 替换照片

推荐准备 **12–18 张**，6 张也能形成一棵树；为手机性能考虑，配置最多使用 36 张。横图、竖图都可以，优先选主体清晰的照片。

1. 把图片放入 `public/photos/`。
2. 修改 `public/photos.json`，删除不需要的示例项，增加自己的照片项。
3. 重新构建并推送部署。

```json
{
  "photos": [
    {
      "src": "photos/photo01.webp",
      "title": "旅途",
      "alt": "山间湖泊的照片"
    },
    {
      "src": "photos/photo02.jpg",
      "title": "日光",
      "alt": "海边日落的照片"
    }
  ]
}
```

`src` 使用相对路径 `photos/文件名`，不要在前面加 `/public/` 或 `/`，这样 GitHub Pages 仓库子路径也能正确加载。文件名大小写要与真实文件一致；建议用简单英文或数字文件名。

支持 JPG、JPEG、PNG、WEBP。HEIC/HEIF 请先转成 JPG 或 WEBP；不同手机浏览器的解码支持不一致，项目会提示转换，避免把 HEIC 当成可普遍使用的网页格式。

建议先将长边压缩到 **1600px 以下、每张 300KB 以下**，Demo 图片长边不超过 960px。应用加载图片时还会降低 GPU 纹理尺寸、控制加载并发，减少图形内存压力；这种运行时优化不能减少原始文件的网络下载大小，原图仍应事先压缩。图片随网页公开部署，访问者可以获取这些文件。

示例图片来源和许可见 `public/photos/CREDITS.txt`，仅用于预览场景。换成自己的照片后，可同步移除示例图片与对应来源项。

## 操作

| 操作 | 效果 |
| --- | --- |
| 单指拖动 / 鼠标拖动 | 带惯性的左右旋转 |
| 双指缩放 | 平滑调整整棵树与照片的大小 |
| 点击照片 | 将照片移动到中央查看 |
| 点击空白 / 关闭照片 | 照片平滑回到原位 |
| 切换场景按钮 | 圣诞树与照片宇宙之间转换 |
| 开启手势控制 | 点击后请求摄像头权限 |
| 左右挥手 | 按手掌移动速度带动旋转 |
| 食指与拇指捏合 | 根据手的位置选中附近照片，松开回位 |
| 两手距离变化 | 调整场景大小 |
| 张开手掌并保持 | 圣诞树扩散成照片宇宙 |
| 在宇宙模式握拳 | 照片与粒子聚合回圣诞树 |

拒绝摄像头、摄像头不可用或识别资源加载失败时会回到触控模式，场景仍可正常玩。手势需要手掌完整进入画面、光线充足，摄像头距离建议让双手能够同时进入画面。

手势模型和 WASM 在开启功能时加载，首次需要网络。渲染与识别分别节流，手势识别不会占用每一帧。摄像头只做本地实时计算，不上传、不保存、不录制画面；预览画面默认隐藏。

## 隐藏愿望券

浏览一段时间或完成一定次数互动后，树顶星星会轻微闪烁。点击星星，镜头靠近并进入愿望券。点击可用的心形后，必须确认“确定使用一次愿望吗？”才会消耗一次。

状态存储在当前域名下的 `localStorage`。刷新、关闭后再次访问仍保留；不同设备、不同浏览器、不同域名不会同步。清理网站数据或使用无法长期保留存储的浏览模式可能使记录重置。Demo 不含服务端核销，因此它不是跨设备的正式兑换账本。

主视觉保留“不得忤逆。”；项目默认愿望必须合法、安全、现实可完成，并且双方自愿。这个默认边界保留在说明与代码中。

## 开发调试

URL 末尾加 `?debug=1` 可启用隐藏调试接口。普通页面不会显示重置按钮。调试模式下，在浏览器控制台执行：

```js
window.photoTreeDebug.resetWishes()
```

可恢复三次愿望，便于测试二次确认和持久化。不要把调试链接作为日常分享链接。

## 手机性能与验证

项目限制像素比，采用按设备等级调整的粒子与烟花预算、共享几何和材质、逐步预加载照片、较小 GPU 纹理以及约 15–24 FPS 的摄像头识别。支持时使用独立 Worker，回退主线程时限制到 15 FPS。页面进入后台时暂停动画与摄像头，返回时恢复所选模式；销毁时释放摄像头轨道、模型、纹理、材质与几何。

优先保证触控与照片查看。低性能或连续掉帧设备会降低视觉预算；关闭手势控制也能减少耗电与发热。页面尊重系统减少动态效果偏好。

开发机与浏览器自动化验证不能代替真实 iPhone Safari 的长时间运行、摄像头权限和发热测试。正式替换照片后，应在目标手机上测试：首次加载、拒绝/允许摄像头、两手操作、聚焦回位、切后台后返回、旋转屏幕、愿望使用后刷新，以及连续运行 5–10 分钟。
